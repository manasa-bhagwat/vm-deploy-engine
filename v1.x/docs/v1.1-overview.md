# v1.1 Overview — Config-Driven Multi-DB Deployment

## Objective
Improve the v1.0 deployment script by adding configuration flexibility, security, and multi-database support.

---

## Enhancements
- Config file: `/etc/app-deploy.conf`
- Secure prompts for:
  - GitHub PAT
  - DB password
- Multi-DB support:
  - MySQL
  - PostgreSQL
  - MongoDB
- Cleaner directory structure
- Better readiness checks
- Stronger environment file permissions

---

## Why v1.1 Matters
This version introduces:
- declarative config
- DB-agnostic provisioning
- better security practices
- early infra-tool structures
- foundation for modular Go CLI in v2.0


---

## 🟦 Run v1.1

```bash
# 1. Clone the project to your local machine
git clone https://github.com/manasa-bhagwat/vm-deploy-engine.git

# 2. Move into the project folder
cd vm-deploy-engine

# 3. Switch to the v1.1 version of the code
git checkout version/1.1
```

✔ You are now looking at only the files that belong to version 1.1.

```bash
# 4. Copy the deployment script + config file to your server's /tmp folder
scp scripts/v1.1/deploy.sh scripts/v1.1/app-deploy.conf.example ubuntu@<server-ip>:/tmp/
```

✔ This uploads both files to your VM.
✔ Replace `<server-ip>` with your actual EC2 / VPS IP.

```bash
# 5. SSH into your server
ssh ubuntu@<server-ip>
```

✔ You are now "inside" the remote Linux machine.

```bash
# 6. Move to the /tmp folder (where you uploaded the files)
cd /tmp
```

```bash
# 7. Move the config file to /etc (the script expects it there)
sudo mv app-deploy.conf.example /etc/app-deploy.conf
```

✔ This becomes your central configuration file.
✔ The script reads DB settings and other values from here.

```bash
# 8. Give execution permission to the script
chmod +x deploy.sh
```

✔ Without this, Linux won’t run the file.

```bash
# 9. Run the deployment script as root
sudo ./deploy.sh
```

✔ It will ask for:

* GitHub PAT (hidden)
* DB username
* DB password (hidden)

✔ Then it performs the full deployment automatically.
